# C++ 本地后端迁移计划

本计划依赖 [C++ 本地后端迁移锚点](./cpp-migration.md)。每一阶段都先完成可观测性和验收，再进入下一阶段。

## 阶段 0：基线和范围冻结

工作内容：

- 记录代表性小、中、大数据集。
- 记录当前启动、导入、轨迹处理、时间轴交互、缓存恢复和导出的端到端耗时。
- 记录峰值内存、renderer 卡顿、IPC 次数和传输字节数。
- 将现有处理链画成实际调用图，标出重复解析和重复派生。
- 明确本阶段不修改的功能和数据格式。

验收：能够用同一批输入复现迁移前结果，并能区分 CPU、I/O、IPC、序列化和渲染耗时。

## 阶段 1：C++ sidecar 基础设施

工作内容：

- 定义 sidecar 启动、握手、版本、请求、进度、取消、错误和关闭协议。
- 建立 C++17 构建脚本和三平台产物布局。
- 在 Electron main 中加入进程生命周期管理，但不迁移业务逻辑。
- 增加异常退出、重复启动、应用关闭和超时回收测试。
- 将 sidecar 纳入 package/make 的资源打包路径。

验收：后端可被启动、探活、取消和干净关闭；不会留下孤儿进程；现有应用功能不变。

## 阶段 2：统一数据摄取

工作内容：

- 将 CSV 读取、字段校验、精度过滤、去重、排序和边界统计迁移到 C++。
- 定义统一的连续内存数据集格式。
- 设计 source fingerprint 和 schema/algorithm version。
- 让 TypeScript 先通过兼容适配层消费 C++ 结果。
- 与现有 TypeScript parser 做双跑比对。

验收：结果与现有实现一致；大文件导入的峰值内存、临时对象数量和 IPC 数据量有明确变化；缓存命中后不重复解析。

## 阶段 3：派生数据和轨迹计算

工作内容：

- 迁移 GPS 清洗、插值、平滑和姿态约束轨迹处理。
- 保留现有 TypeScript 实现作为对照实现一段时间。
- 支持任务进度、取消和分段失败诊断。
- 统一输出轨迹、上下文点和诊断信息，避免 renderer 再组装多份数组。

验收：迁移前后轨迹在规定误差内一致；处理期间 UI 保持可交互；取消和关闭行为可靠；内存峰值和端到端耗时有基准结果。

## 阶段 4：时间轴指标和缓存

工作内容：

- 将速度、密度、平滑曲线等可缓存指标移入 C++ core。
- 以时间范围、显示分辨率和算法版本作为缓存键。
- renderer 只请求当前视窗需要的结果，不持有完整计算过程。
- 评估是否需要预聚合、多分辨率索引或按需计算。

验收：拖动和缩放时间轴不会触发全量重复计算；结果和显示行为与现有版本一致；缓存命中和失效可观测。

## 阶段 5：清理旧链路

只有阶段 0–4 的结果满足验收后才执行：

- 删除已被替代的重复 TypeScript 计算路径。
- 删除不再需要的中间数组和重复缓存。
- 统一任务错误、进度和取消模型。
- 补充文档、打包说明和故障排查说明。
- 完成三平台构建和实际打包验证。

## 风险和应对

| 风险 | 应对 |
| --- | --- |
| C++ 结果与旧实现有细小差异 | 双跑、固定测试样本、明确浮点误差范围 |
| sidecar 通信抵消计算收益 | 使用二进制数据面；必要时再评估 C ABI/N-API |
| 应用退出时后端残留 | 先实现进程树回收和超时兜底，再接入业务任务 |
| 缓存格式升级导致旧数据不可读 | schema version + 安全失效 + 保留旧读取路径 |
| 三平台编译链不一致 | 每阶段都在三平台验证，不把跨平台推迟到最后 |
| 当前未提交修改产生冲突 | 迁移分支只处理迁移文件，合并前逐项解决冲突 |

## 当前执行顺序

已接通阶段 1 的构建、打包资源配置、版本握手、探活和退出路径。Electron 主进程创建窗口后发起探活。版本 1 用标准输入和标准输出各传一行 ASCII，`hello 1` 对应 `ready 1`，`ping` 对应 `pong`，关闭标准输入触发退出。任务 ID、进度和取消将在接入首个业务任务时一并实现。

运行 `npm --prefix source run check:native-core` 可用真实 C++ 进程验证接口。开发启动和打包时由 Forge 构建本机产物，需要 C++17 编译器。macOS 和 Linux 默认使用 `c++`，Windows 默认使用 MinGW-w64 的 `g++.exe`，可用 `CXX` 指定兼容编译器。

业务迁移前仍需完成阶段 0 的端到端基线。
