# DJI 视频、GPS 与姿态时间对齐实验

实验日期：2026-11-11。研究使用本机真实视频与足迹数据，未改写原视频、GPS 或应用处理流程。

## 本次结论

`RawData/video/DJI_20261101164401_0356_D.MP4` 的容器时间为北京时间 2026-11-01 16:44:02。视频中手机状态栏提供了另一个时钟：

| 视频时刻 | 画面中手机时间 |
| --- | --- |
| 27.00 秒 | 16:43 |
| 28.52 秒 | 16:44 |

假定手机时钟与 GPS 的 Unix 时间一致，并暂不计状态栏刷新延迟，视频第 0 秒对应 **16:43:31.48 至 16:43:33.00**，比容器日期早约 **30 秒**。

统一符号约定：

```text
GPS_epoch = nominal_video_epoch + video_seconds + offset_seconds
本次 offset 约为 −30 秒
```

上述观察约束为 `[-30.52, -29.00]` 秒，**不是精度保证或统计置信区间**。手机时间是否自动同步、显示刷新和 GPS 记录延迟都需要另计。以约 −30 秒作为本段时钟对齐初值是有证据的；尚不能宣称 GPS 测量与视频实现了亚秒同步。

手机导航速度的 10 个人工读数与足迹 CSV 的速度序列，在前后各 600 秒搜索中给出最优候选 **−32.0 秒**，RMSE 约 **4.59 km/h**。计算暂按 CSV `speed` 为 m/s、乘 3.6 比较；它与显示速度的一致性支持这个解释，输入格式本身还未保证单位。显示读数与 CSV 不是独立真值，采样和刷新也不同，因此这个结果用于支持约 −30 秒的范围，不能覆盖时钟证据而强定 −32.0 秒。

## 实际数据

- 视频为 Osmo Action 4，1920×1080、25 fps；主视频时长 68.92 秒。
- 包含 djmd、dbgi、音频和时间码轨。
- 本次 ExifTool 解码得到 1,723 个姿态样本，时间 0～68.88 秒，间隔 0.04 秒。
- 同一批样本有三轴加速度。本次没有提取得到视频内 GPS 坐标或 GPSDateTime。
- 四元数归一化后旋转加速度，三个分量的中位数约为 `[-0.0096, -0.0049, -1.0023]`。这支持姿态和加速度之间存在合理的重力关系，也提示加速度近似以 g 为单位，但不等于已经完成传感器标定。
- 完整足迹 CSV 有对应时段；搜索上下文中的 GPS 采样间隔中位数为 6 秒，部分更长。`heading` 为零，实验用相邻坐标计算航向。
- `backUpData-all.csv` 对应时段与年度文件的数据相同，不能当成第二个独立定位来源。`Example_footprint.csv` 没有本段对应时刻。
- 视频旁的 698 字节 `.MP4.csv` 只有元信息及列名，没有可用的陀螺仪样本行。

本次只确认了解码出来的每帧数据，没有证明 dbgi 等轨中不存在其他高频传感器数据。

## 为什么只匹配陀螺仪会错

实验对归一化 WXYZ 四元数的 X/Y 两种水平投影分别搜索，并测试正反航向关系。GPS 航向视为每段的位移方向，与同段平均姿态比较，拟合一个固定安装角；要求至少 7 段、覆盖比较窗口至少 75%，排除大于 18 秒的段与不足 10 米的位移。

| 方法 | 最优候选偏移 | 误差 | 结论 |
| --- | --- | --- | --- |
| 水平姿态曲线匹配 | +58.0 秒 | 航向 RMSE 3.26° | 与画面手机时钟冲突，排除 |
| 水平姿态曲线的另一局部候选 | −23.5 秒 | 航向 RMSE 3.55° | 也不能单独作为时钟锚点 |
| 手机速度与 GPS 速度匹配 | −32.0 秒 | 速度 RMSE 4.59 km/h | 支持约 −30 秒，仍有采样与延迟误差 |
| 手机状态栏跳分钟 | −30.52～−29.00 秒 | 观察边界，不含刷新误差 | 本次最直接的时钟约束 |

不同误差单位不能直接横向比较。搜索评分也不是匹配概率。

本段开头画面从手套、车把转到前方，说明相机存在独立于车辆的转动。首个 5 秒的姿态变化约 57°，不能全部解释成道路转弯。即使去掉开头，镜头与行进方向的关系也未必恒定。**数据不足时，错误路段仍可能得到更漂亮的航向误差。**

在约 −30 秒的时钟约束下，当前简单姿态模型的航向残差约为 7～8°；这比错误的 +58 秒候选更大。可能包含相机相对车身转动、坐标轴安装误差、GPS 滤波或时间延迟，现有实验无法唯一归因，不能通过擅改时钟或拉伸时间轴把它强行消掉。

四元数 WXYZ 顺序有 DJI 元数据协议定义支持；Gyroflow 的解析器也明确执行了坐标旋转。我们的实验投影只是用于探索候选，尚未完成车辆坐标系的标定。

## 适合项目的对齐方式

1. **分开保存时钟变换和传感器延迟。** 视频日期只作初值，先估计时钟偏移；GPS 缓存、滤波或回调延迟作为另一个待验证量。不要把姿态与 GPS 的差异全归成时钟漂移。
2. **先搜索偏移，再考虑漂移。** 通常先用 `t_project = t_source + b`，在用户预期的数分钟范围内搜索并保留多个峰。长素材有多个可靠锚点时才拟合 `a × t + b`。本段 69 秒不足以可靠区分微小时钟漂移与相机转头。
3. **有可读时钟、时间码或可靠内嵌 UTC 时，优先建立锚点。** 本次手机跳分钟比单纯转弯匹配可靠。没有这类证据时，用连续左右弯、速度变化等组合特征匹配，并要求前后分段验证，候选不唯一就输出“待确认”，不自动修轨。
4. **姿态只在可信片段内充当软约束。** 检测开头调整相机、转头、低头及低速 GPS 航向不稳定区间；固定在车身且完成安装角标定时，才提高方向约束权重。
5. **GPS 与姿态先在真实时间中处理。** 成片时刻通过变速映射反查原视频时刻，再映射到 GPS 时间；不能在加速时间中估计真实车辆速度或积分加速度。

## 对 GPS 修正和插值的影响

建议先做保留原始数据的离线轨迹估计：GPS 按 accuracy 加权，在局部米制坐标下联合平滑位置和速度；长缺口分段，不能自动连成确定路线。姿态为可靠片段提供转弯时序及方向变化约束，允许相机与车辆之间有变化的角度与不确定性。

本段暂不适合把镜头 yaw 直接写成轨迹航向，也不适合把每帧加速度直接双积分成“修正后 GPS”。近似重力单位、坐标轴、偏置和相机相对车身运动都尚未完整标定。姿态可以先用于减少弯道插值切角，但必须保留置信度；遇到冲突应降低姿态权重，而不是把可靠 GPS 拉向相机视线。

验证应至少包含：

- 把部分 GPS 点留出，比较线性插值、仅 GPS 平滑和姿态辅助平滑的预测误差；
- 检查不同片段估计的偏移是否一致，候选是否明显优于其他路段；
- 检查实际转弯时刻、速度连续性和定位不确定性，避免只评估曲线是否好看。

留出的 GPS 仍然含测量误差；要证明绝对定位精度提高，需要独立参考轨迹。

## 复现

脚本只用 Python 标准库，报告原始候选与限制，不自动改变视频或轨迹。手工画面读数明确存于观察文件，并未实现自动 OCR。

```bash
.tools/exiftool/exiftool -ee -j -G3:1 -n -api LargeFileSupport=1 \
  -SampleTime -SampleDuration -Quaternion1 -Quaternion2 -Quaternion3 -Quaternion4 \
  -AccelerometerX -AccelerometerY -AccelerometerZ -GPSLatitude -GPSLongitude -GPSDateTime \
  RawData/video/DJI_20261101164401_0356_D.MP4 \
  > outputs/research/time-alignment/telemetry.json

python3 source/scripts/tools/research-dji-gps-alignment.py \
  --telemetry outputs/research/time-alignment/telemetry.json \
  --gps RawData/footprint/2026.01.01-2026.12.31.csv \
  --nominal-start 2026-11-01T16:44:02+08:00 \
  --observations outputs/research/time-alignment/observations.json \
  --out outputs/research/time-alignment/result.json
```

证据帧以精确 seek 或原始帧号导出。注意 `fps=1/N` 的缩略图通常选择时间格内的帧，不能把第一张图直接标为 0 秒。本次时钟观察使用精确定位，第 28.5 秒 seek 对应 25 fps 的第 28.52 秒帧。

本机 `outputs/research/time-alignment/` 保存遥测、画面读数、证据图片、完整扫描结果和 `validation.json`，不进入 Git。脚本一致性验证通过：把名义起点提前 120 秒，姿态、速度和时钟三种偏移结果均增加 120 秒；同时验证数字字符串解析及角度跨 360° 的处理。这些检查验证实现与符号，不证明实际定位精度。
